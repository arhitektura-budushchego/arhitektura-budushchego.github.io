# Разрешённые коды источников

`attribution.json` — общедоступный список разрешённых кодов. JavaScript не нужно менять при добавлении площадки. В этом файле запрещены имена, email, тексты обращений, ссылки с секретами и идентификаторы читателей. Не публикуйте выгрузку закрытого реестра целиком.

Для новой площадки:

1. В общем реестре назначьте общедоступный `source_id` для места публикации и `campaign_id` для кампании. Используйте код организации, а не адресата или читателя.
2. Добавьте эти коды в массивы `sources` и `campaigns` файла `attribution.json`. Существующие коды не переименовывайте; удаление кода прекращает его дальнейшую атрибуцию.
3. Если существующий вид кода неудобен, используйте универсальный код места `p001`…`p999` и кампании `c001`…`c999`. Для новых платформ изменение JavaScript тоже не требуется.
4. Проверьте JSON и выполните браузерные тесты. Зафиксируйте изменение настроек обычным PR. После публикации файла ссылка может содержать только `?utm_campaign=КОД&utm_source=КОД`.

Совместимые прежние коды: `r048_email`, `r018_review01`, `own_yt_video01`, `reader_share`; кампании `pilot01`, `organic01`, `test01`, `bloggers01`. Исходный файл включает коды зарегистрированных ресурсов R001–R049 с пропусками отсутствующих R010–R012. Наличие кода не означает утверждение обращения или публикации: эти решения остаются в закрытом реестре.

Формат — объект ровно с полями `version: 1`, `campaigns: [...]`, `sources: [...]`. Ограничения: 100 кампаний, 2000 источников, размер 131072 символа. Повторяющиеся коды, неизвестные поля, неподдерживаемая версия, произвольные строки, email и повреждённый JSON отвергаются целиком. При ошибке/недоступности файла параметры кампании не передаются; обычный учёт просмотров и страница продолжают работать. Запрос настроек ограничен пятью секундами.

Разрешены только коды, одновременно присутствующие в конфигурации и соответствующие строгому техническому формату. Неизвестные параметры URL, якорь, повторные utm-поля и значения вне списка исключаются. Кампания не сохраняется в браузере и не переносится на следующую страницу. Конфигурация задаёт размещения, а не отдельные переходы и людей. Проверка формата не заменяет проверку смысла кодов человеком перед публикацией.

Тесты `tests/attribution.cjs` проверяют добавление новой кампании и источника только заменой JSON, удаление кода, действующие редакционные и блогерские коды, попытки передать персональные данные и безопасное поведение при ошибке файла. Нужны Playwright, Chromium и переменные `CHROMIUM_EXECUTABLE`, `GOATCOUNTER_TRACKER_SOURCE` с локальной копией официального счётчика. Сеть в тестах перехватывается. Серверная проверка GoatCounter выполняется отдельно и не является условием публикации интерфейсных разделов.
